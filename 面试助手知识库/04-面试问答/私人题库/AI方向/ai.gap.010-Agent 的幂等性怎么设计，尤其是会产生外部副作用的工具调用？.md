# Agent 的幂等性怎么设计，尤其是会产生外部副作用的工具调用？

> [!warning] 阅读边界
> 证据：草稿待核对（draft）；审核：待CC审核（cc_pending）。状态沿用源库，本次导入未重新核验事实。 请先核对项目事实与指标，再用于面试口述。

先尝试口述，再展开源库答案。

> [!note]- 源库答案（原文）
> 幂等性不能只靠提示模型“不要重复调用”，必须由运行时和工具共同保证。每个逻辑动作生成稳定幂等键，通常由任务 ID、步骤 ID、工具版本和规范化业务参数组成；调用前先在副作用账本登记 pending，工具端以该键去重并返回第一次结果。超时后不能直接重试，要先查询原调用状态，区分未执行、执行中和已成功。状态更新使用事务、唯一约束或乐观锁，消息消费采用 inbox/outbox 防重。对于本身不支持幂等的外部系统，应加适配层、业务唯一号或人工确认；不可逆动作还要设计补偿和审计，明确幂等记录的保留期限。
