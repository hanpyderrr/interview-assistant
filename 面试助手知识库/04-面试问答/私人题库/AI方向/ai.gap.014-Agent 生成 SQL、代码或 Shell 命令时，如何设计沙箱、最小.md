# Agent 生成 SQL、代码或 Shell 命令时，如何设计沙箱、最小权限和人工确认？

> [!warning] 阅读边界
> 证据：草稿待核对（draft）；审核：待CC审核（cc_pending）。状态沿用源库，本次导入未重新核验事实。 请先核对项目事实与指标，再用于面试口述。

先尝试口述，再展开源库答案。

> [!note]- 源库答案（原文）
> 如果由我设计，会把“生成”和“执行”彻底分离。模型只输出结构化意图或候选命令，策略层先做语法解析、危险操作识别、资源范围和身份校验，再决定拒绝、沙箱执行或请求人工确认。沙箱使用临时文件系统、非特权用户、只读挂载、网络白名单、CPU/内存/时长限制，并禁用凭据继承；SQL 默认只读、限定库表和行数，写操作走独立受控通道。人工确认展示将执行的规范化命令、目标、影响和不可逆性，批准令牌绑定内容且短期有效。执行后记录审计、限制输出并清理环境，任何文本规则都不能替代操作系统和数据库的强隔离。
