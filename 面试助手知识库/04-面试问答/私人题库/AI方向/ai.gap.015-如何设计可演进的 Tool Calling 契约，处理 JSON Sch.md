# 如何设计可演进的 Tool Calling 契约，处理 JSON Schema、参数校验、工具版本、未知工具、部分结果和重复调用？

> [!warning] 阅读边界
> 证据：草稿待核对（draft）；审核：待CC审核（cc_pending）。状态沿用源库，本次导入未重新核验事实。 请先核对项目事实与指标，再用于面试口述。

先尝试口述，再展开源库答案。

> [!note]- 源库答案（原文）
> 契约要稳定、可版本化并由运行时强校验。每个工具使用唯一名称和语义版本，输入输出都发布 JSON Schema；调用前做类型、范围、枚举、互斥字段及业务约束校验，默认拒绝未知字段。破坏性变更发布新版本，旧会话固定原版本并设置退役窗口。运行时遇到未知工具要返回机器可读错误和当前可用列表，不能猜测映射。响应统一表达成功、部分成功、失败、待定和可重试性，逐项结果带独立状态。重复调用通过 stepId、参数指纹和幂等键去重，若同键参数不同则拒绝。还要用契约测试和回放验证新旧客户端兼容。
