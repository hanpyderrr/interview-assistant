# 如何通过反思机制提升 Agent 任务成功率，同时控制额外成本和延迟？

> [!warning] 阅读边界
> 证据：草稿待核对（draft）；审核：待CC审核（cc_pending）。状态沿用源库，本次导入未重新核验事实。 请先核对项目事实与指标，再用于面试口述。

先尝试口述，再展开源库答案。

> [!note]- 源库答案（原文）
> 反思应是按风险触发的校验环节，而不是每一步都让模型再想一遍。先为任务定义可检查的失败信号，例如工具报错、证据不足、输出不满足 schema 或置信度低；命中信号时，再让模型基于原目标、轨迹和失败证据生成有限的改进建议。反思最多修正局部计划或重试少数次数，超过预算就降级或交给人工。低风险任务可抽样反思，高风险输出则结合规则、测试或独立评审模型。效果要用任务成功率增益对额外 Token、延迟和误修率评估，防止“越反思越偏”。
