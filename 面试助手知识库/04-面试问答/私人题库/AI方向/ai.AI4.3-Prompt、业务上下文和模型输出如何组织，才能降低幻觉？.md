# Prompt、业务上下文和模型输出如何组织，才能降低幻觉？

> [!warning] 阅读边界
> 证据：草稿待核对（draft）；审核：待CC审核（cc_pending）。状态沿用源库，本次导入未重新核验事实。 请先核对项目事实与指标，再用于面试口述。

> [!note]- 源库答案（原文）
> 系统 Prompt 明确角色、边界、数据来源和禁止事项；业务上下文只放与任务相关的结构化摘要，并标注日期、来源和不确定性；用户问题与检索片段分隔，要求模型只基于给定资料回答，缺失就说明不知道。需要执行动作时让模型输出受约束的结构，而不是自由文本。后端再校验输出和权限，不能把 Prompt 约束当成安全边界的唯一防线。离线评测错误案例后持续修订模板。
