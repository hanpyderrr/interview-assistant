# 大量 Agent 任务并发时，如何设计模型、工具和子任务的预算、背压、公平调度与过载保护？

> [!warning] 阅读边界
> 证据：草稿待核对（draft）；审核：待CC审核（cc_pending）。状态沿用源库，本次导入未重新核验事实。 请先核对项目事实与指标，再用于面试口述。

先尝试口述，再展开源库答案。

> [!note]- 源库答案（原文）
> 如果由我设计，会给每个请求建立可递减的总预算，覆盖 Token、工具调用数、子任务数、并发和 deadline，再把额度分配给各步骤，子 Agent 不能自行扩张。入口按租户和优先级准入，队列有界；模型、每类工具和子任务分别设置并发舱壁、速率限制与超时，慢消费者通过背压降低上游生产。调度采用加权公平队列或 deficit round robin，结合租户配额与任务成本估计，避免大任务或大客户饿死其他请求。过载时依次拒绝低优先级新任务、减少并行和候选数、切换小模型或返回部分结果；重试也消耗预算并带抖动，防止雪崩。
