# Agent 中的状态和上下文有什么区别，为什么不能只依赖聊天历史保存状态？

> [!warning] 阅读边界
> 证据：草稿待核对（draft）；审核：待CC审核（cc_pending）。状态沿用源库，本次导入未重新核验事实。 请先核对项目事实与指标，再用于面试口述。

先尝试口述，再展开源库答案。

> [!note]- 源库答案（原文）
> 状态是系统必须准确持久化的事实，例如任务阶段、已完成步骤、工具调用 ID、审批结果和版本；上下文是本次模型推理可见的信息包，可能包含聊天、摘要、检索证据和状态投影。聊天历史是面向交流的文本，容易被截断、压缩、歧义表达，也缺少事务和并发控制，因此不能充当唯一状态源。正确做法是把关键状态存入结构化存储，通过状态机和版本控制更新；每次调用模型时再按需要把状态投影为上下文。这样即使上下文窗口变化、会话重连或模型误读，任务仍能可靠恢复和审计。
