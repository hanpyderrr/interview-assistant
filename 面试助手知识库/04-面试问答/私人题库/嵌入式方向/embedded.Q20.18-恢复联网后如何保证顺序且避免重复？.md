# 恢复联网后如何保证顺序且避免重复？

> [!warning] 阅读边界
> 证据：草稿待核对（draft）；审核：待CC审核（cc_pending）。状态沿用源库，本次导入未重新核验事实。 请先核对项目事实与指标，再用于面试口述。

先尝试口述，再展开源库答案。

> [!note]- 源库答案（原文）
> 恢复联网后，从队头按记录单调序号依次上传，每收到一条能够证明服务端确实接收的确认后，才推进队头指针。若网络恰在服务端已接收、客户端未收到确认的时刻断开，重传会产生重复记录，因此服务端必须按设备 ID 加序号做幂等去重。该实现通常是至少一次投递，而不是承诺绝对不重复。；说明至少一次投递与应用层幂等去重的配合关系，确认丢失时重传相同序号由服务端按设备 ID 加序号去重。
