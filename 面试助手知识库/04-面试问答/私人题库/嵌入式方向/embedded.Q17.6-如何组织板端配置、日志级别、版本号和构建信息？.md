# 如何组织板端配置、日志级别、版本号和构建信息？

> [!warning] 阅读边界
> 证据：草稿待核对（draft）；审核：待CC审核（cc_pending）。状态沿用源库，本次导入未重新核验事实。 请先核对项目事实与指标，再用于面试口述。

先尝试口述，再展开源库答案。

> [!note]- 源库答案（原文）
> 将硬件相关配置按 board/variant 分层，公共默认值与产品差异分离；日志采用编译期最高级别加运行时过滤；版本号来自受控版本文件或 Git 标签，构建时生成只读的版本、提交、工具链和功能配置清单。可复现构建中不要无条件嵌入当前时间或绝对路径；密钥与环境特定秘密不能进入源码和构建日志；配置要有 schema/版本并做启动校验。设备诊断接口输出固件版本和构建 ID，问题日志能回溯到源码与配置；实际是否使用 Git describe、CI 编号等按项目回答。
