# SPI 没有 TCP 意义上的粘包、半包，简历为何用这两个词？实际处理什么问题？

> [!warning] 阅读边界

> [!note]- 源库答案（原文）
> 这里的粘包、半包只是类比应用读取边界与协议帧边界不一致，不是说 SPI 有 TCP 的字节流分段机制。真正问题是一次用户态 read 或一次底层传输可能只覆盖一帧的一部分，也可能包含一帧尾部和下一帧开头；此外还可能从任意字节位置开始、出现丢字节或噪声。准确表述：应改为处理 SPI 读取块与应用协议帧边界不一致的问题，通过持久解析缓存、帧头/长度/CRC 和状态机完成跨批次拼接、多帧提取及错误重同步。边界：具体为何产生这种分块，要结合驱动缓冲、传输长度和采集模块行为说明，不能把 TCP 术语原样套用到 SPI 总线。
