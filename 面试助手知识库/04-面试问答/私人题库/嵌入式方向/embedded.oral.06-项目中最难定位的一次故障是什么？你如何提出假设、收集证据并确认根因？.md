> [!note]- 源库答案（原文）
> 源文件已按真实项目经历补齐（PF32 TRIG 无输出），可背诵；口径与旧简历'DMA 通信异常'不一致，面试前必须统一。故障闭环：现象——激光切外触发后不出光、系统无法成像；假设——PF32 sys_master 的 TRIG 输出缺失或 FPGA 固件不支持 TDC 时序；证据——示波器探 PF32 TRIG SMA 无信号，Python 直调 SDK（1.5.21/1.5.25）设置 TCSPC_sys_master + EXTSTOP 后，直方图计数正常（约 2500/帧暗计数）但 peak_bin 全为 0、sync=0Hz；排除——两版 SDK 均复现、USB 链路正常，排除调用与接线；根因——FPGA 固件是光子计数流版本，无 TRIG 输出电路，setMode 被接受但无硬件效果；方案与复测——改用 Si5351A 双路同源外触发（CLK0→激光 P3、CLK1→PF32 SYNC，500kHz），PF32 跑 TCSPC_laser_master，Si5351A I²C 初始化与两路输出验证通过。要点：软件 API 返回成功不等于硬件功能存在，结论必须用示波器波形与计数数据支撑；此案例也解释了项目同步方案为什么是外部时钟双路驱动。 证据边界：本条复测仅确认Si5351A的I²C初始化与双路时钟输出，未给出此次改造后整机重新出光成像的验收结果，也未给出双路相位差、抖动等同步精度测量；不能把方案配置或输出测试扩写为这些结果已全部验证。

> [!note]- 源库补充全文（原文）
> 单光子成像系统联调中最难定位的一次故障，是激光切外触发后不出光、系统无法成像。我当时的假设是 PF32 探测器 sys_master 模式的 TRIG 输出有问题，或者 FPGA 固件不支持 TDC 时序输出。证据分三层：先用示波器探 PF32 的 TRIG SMA 口，确认完全没有信号；再用 Python 直调 SDK 的 C API，1.5.21 和 1.5.25 两个版本都试了，链路状态正常后设置 sys_master 并开启 EXTSTOP，读回配置正确，直方图计数也正常，每帧约两千五百个暗计数，但所有计数的 peak_bin 都是零、sync 是零赫兹——有光子计数、没有时间信息。两个 SDK 版本都复现，排除了调用方式和接线的问题。最终根因是 FPGA 固件：PF32_USB3.bit 是光子计数流版本，本身没有 TRIG 输出电路，SDK 接受了 setMode，但硬件上没有对应实现。解决方案是换同步架构：用 Si5351A 时钟芯片双路同源外触发，一路驱动激光外触发，一路接 PF32 的 SYNC，500kHz，PF32 改跑 laser_master 模式，用外部 SYNC 做时序参考；Si5351A 的 I²C 初始化和两路输出都验证通过。这次排障给我的教训是：软件 API 返回成功不等于硬件功能存在，每个环节都要用示波器波形和计数数据验证。
