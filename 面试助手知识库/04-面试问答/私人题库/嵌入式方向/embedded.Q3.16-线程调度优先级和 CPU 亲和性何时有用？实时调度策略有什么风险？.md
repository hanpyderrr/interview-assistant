# 线程调度优先级和 CPU 亲和性何时有用？实时调度策略有什么风险？

> [!warning] 阅读边界
> 证据：草稿待核对（draft）；审核：待CC审核（cc_pending）。状态沿用源库，本次导入未重新核验事实。 请先核对项目事实与指标，再用于面试口述。

先尝试口述，再展开源库答案。

> [!note]- 源库答案（原文）
> 当采集线程有明确延迟预算、需减少迁核抖动或隔离 CPU 干扰时，可设置亲和性；优先级用于表达对调度延迟的相对要求。普通策略下 nice 值影响公平调度；SCHED_FIFO/RR 等实时策略可让高优先级线程优先运行。风险：实时线程若忙循环、不阻塞或优先级设计错误，可能饿死 UI、网络乃至系统维护线程；锁竞争还会产生优先级反转，需要优先级继承等机制；亲和性过度绑定会降低负载均衡并形成热点。项目结合：应先测量采集抖动和丢帧，再最小化关键路径、设置资源上限和看门狗；不能仅凭实时标签提高权限。
