## 先补六个问题

| 主题 | 应该能回答的问题 | 建议留下的验证产物 |
| --- | --- | --- |
| 输入与输出 | 尺寸、颜色顺序、归一化、布局和后处理怎样保持一致？ | 固定样本的输入张量说明和输出对比 |
| 模型转换 | 原模型转为ONNX或目标格式后，如何检查输出偏差与算子兼容？ | 模型版本、转换配置、误差比较 |
| 量化 | 浮点与INT8如何取舍，校准数据应如何选择，如何检查质量变化？ | 固定评测集上的质量与耗时对比 |
| 目标平台 | CPU、GPU、NPU各在链路中承担什么，如何确认实际执行位置？ | 环境版本、运行日志、性能观测 |
| 流水线性能 | 采集、预处理、推理、后处理、显示分别耗时多少？ | 分阶段耗时、端到端延迟和内存曲线 |
| 持续运行 | 队列满、模型失败、设备掉线或长时间运行如何处理？ | 异常注入、恢复结果和持续运行记录 |

## 选择一条工具路线
- 先在当前可用计算机上建立输入输出一致的基线，可阅读 [ONNX Runtime 文档](https://onnxruntime.ai/docs/)。没有目标板时先完成基线，不报告板端性能。
- 如果目标岗位和可用硬件采用 RK3568 等 Rockchip 平台，阅读 [RKNN-Toolkit2 官方仓库](https://github.com/airockchip/rknn-toolkit2)。官方流程区分模型转换工具、板端API和运行环境；实际操作前核对芯片、SDK与驱动兼容性。
- 如果岗位采用 NVIDIA 平台，再阅读 [TensorRT 性能指南](https://docs.nvidia.com/deeplearning/tensorrt/latest/performance/best-practices.html)。不需要为三种岗位同时配置所有平台。
- 量化入门参考 [ONNX Runtime 量化说明](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)。先比较固定数据上的质量和速度，再讨论是否值得量化。
